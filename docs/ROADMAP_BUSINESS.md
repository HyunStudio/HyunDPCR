# 개발·검증·사업화 로드맵 v1.1

**기준일:** 2026-11-13 · **기간/가격은 시장검증 전 기획 가설** · **우선순위:** 안전/데이터/수요 검증 > 알고리즘 복잡성

## 1. 북극성 지표

**검증 가능한 제품 가치:** 사용자가 동일 데이터·임상 조건에서 시간 갱신 위험과 진단 경로를 비교하는 연구를 더 **재현 가능하고 정확하게 수행**할 수 있는가?

상업화의 성공은 앱 다운로드 수보다 **연구조직의 반복 이용과 구매 의사, 데이터 권리, 임상적 신뢰, 검증된 분석 성능**에 의해 판단한다.

## 2. 단계별 로드맵

| Phase | 가안 일정(착수 기준) | Deliverable | Gate |
|---|---|---|---|
| **0. Discovery** | 0–3주 | 임상의/연구자 인터뷰, 첫 코호트/시장/결과 정의, 데이터 접근 현황 | 고객문제와 데이터 근거 확보 |
| **1. Synthetic Research MVP** | 3–10주 | Signal/Guard, 합성 타임라인, 기준선, 시뮬레이션 화면, 재현 가능한 보고서 | 누수·시뮬레이션·사용성·안전 테스트 |
| **2. Real-world feasibility** | 2–6개월 | 승인된 데이터 사전·후향적 코호트·예측 기준선·검증 계획 | IRB/DUA, 분모·결과 확인, 데이터 품질 |
| **3. External validation / paid pilot** | 6–12개월+ | 독립기관·시간 검증, 업무흐름 평가, 유료 연구 파일럿 | 실제 가치/구매자, 임상적 순편익 근거 |
| **4. Clinical CDS (optional)** | 별도 결정 | 규제·품질·의료진 workflow·안전 운영 | 관할권별 인증/허가·법적 책임·현장 안전 |

일정은 채용·데이터 접근·파트너십과 규제 심사에 따라 대폭 달라질 수 있으며 약속된 출시일이 아니다.

## 3. 90일 실무 백로그

### Sprint A — Define (1–2주)

- [ ] 성인 비특이적 증상 코호트의 첫 임상 시나리오 **하나** 선정
- [ ] 임상 자문/통계 자문 후보 확인, NICE 등 시장별 지침 적용 가능성 검토
- [ ] 구매자/사용자 인터뷰 질문지 제작; 첫 5건 진행
- [ ] 암 진단 endpoint, as-of, 수평선, 경쟁사건 명세 승인
- [ ] 데모에서 절대 주장하지 않을 임상 문구 목록 확정

### Sprint B — Build (3–6주)

- [ ] 합성 데이터 생성기(고정 seed, 이벤트 타임스탬프)
- [ ] 시간 갱신 기준선 및 모델 카드
- [ ] 누수·불변식 테스트 자동화
- [ ] Signal 타임라인 UI + 불확실성·증거 표기
- [ ] Guard 보고서 및 접근성 검사
- [ ] 연구보고 내보내기(가상 경고)

### Sprint C — Compare (7–10주)

- [ ] 확률적 Pathway 대기열/상태전이 시뮬레이션
- [ ] 옵션별 VOI 연구 데모(임상적 입력 가정 필수)
- [ ] 각 모델 ablation, 테스트 가정표, 구조적 민감도 분석
- [ ] 임상의에게 안전 제약 검토 요청
- [ ] 비교 task usability 5–8건(목표) 수행

### Sprint D — Decide (11–13주)

- [ ] 추가 7–10명 사용자/구매자 인터뷰
- [ ] 데이터 이용/IRB 가능성 확보 및 개념검증 파트너 협의
- [ ] 첫 유료 파일럿 제안/범위·보안·책임·고객 지원 구조 작성
- [ ] go/no-go: 고객문제, 데이터, 검증, 위해, 구매 흐름 모두 점검

## 3.1. Engineering MVP 구현 게이트 (2026-11 아키텍처 확정)

- **M0 — 기초구조:** pyproject.toml, lockfile, src/hyundpcr/services, app/Home.py, examples/synthetic, tests, GitHub Actions. **기획 완료 / 실제 파일·CI 미구현**.
- **M1 — Signal/Guard:** Python 입력 계약, 고정 seed 합성 타임라인, 첫 방문~재진 위험 추정, 모델·데이터 버전 감사, 연구 전용 워터마크.
- **M2 — Pathway:** 분석엔진을 Streamlit에서 분리한 상태로 검사·의뢰·대기열 시뮬레이션. 수평선/시간 가용성 보존.
- **M3 — Options:** 허용된 정책만 대상으로 VOI/비용·위해 시나리오. 가정 누락 시 계산 비활성화.
- **M4 — 외부 연구/상용화 준비:** 기관 수요가 검증되면 FastAPI + 인증·감사 + 기관 승인을 받은 저장소; React·PostgreSQL은 실제 요구가 확인될 경우에만.

**개발의 Definition of Done:** 새 환경에서 프로젝트 설치·pytest·Streamlit 실행 가능, 미래정보 누출 테스트 통과, 결과/내보내기 비임상 경고 누락 없음, 인터페이스는 키보드·확대·표/텍스트 요약으로 접근 가능.

**스택 확정:** Python 3.12+, Streamlit-first; 초기부터 FastAPI와 React를 병행하지 않는다. 상세 기술 구성은 [ARCHITECTURE.md](ARCHITECTURE.md) 참조.

## 4. 사업 모델 가설

| Tier | 판매 대상 | 제공 | 선행 요구 |
|---|---|---|---|
| Academic Research Workspace | 연구팀 | 합성·비식별 승인 데이터 분석, 시뮬레이션, 보고서 재현성 | 연구계약, 데이터 권한, 기술 지원 |
| Institutional Pilot | 의료기관 연구·운영혁신팀 | 대기열 시나리오·평가 리포트·감사 | 기관 프로젝트 승인/보안 |
| Enterprise Integration | 병원/EMR 사업자 | 현지화 API·모델 거버넌스·SLA | 외부 검증, 규제, 보안 및 책임 계약 |
| Clinical Decision Support | 의료진 | 실제 사용 목적에 맞는 안전한 워크플로우 | 규제 및 임상 유효성 검증이 완료된 경우에만 |

**가격 전략:** 현재 공개 경쟁 계약 가격이나 실제 지불의사 조사 결과 없음. 임의의 '시장 평균 연간 라이선스' 금액 제시 금지.

**견적 방식 가설:** 연구 규모, 기관 수, 데이터 보관·연동, 모델 검증/자문, 지원 수준을 항목화하여 유료 PoC 가격 제안 후 WTP 확인. HIPAA/GDPR/PIPA 관련 법무·계약 비용은 별도.

## 5. 고객 인터뷰 8문항

1. 지금 다루는 암 진단 경로와 분석 목적은 무엇인가?
2. 실제 데이터는 어떤 승인과 환경에서 사용할 수 있는가?
3. 현재 어떤 도구로 환자의 재진·검사·진단 이력을 결합하는가?
4. 임상 연구 결과 재현이나 설명에 걸리는 가장 큰 시간이 무엇인가?
5. 위험 점수 대신 검사/의뢰 정책 가정 비교에 실무 가치가 있는가?
6. 어떤 성능·보안·연동 기준을 못 채우면 쓰지 않겠는가?
7. 예산 승인자는 누구이며 유료 파일럿의 평가 기준은 무엇인가?
8. 지금 쓰는 제품 대비 부족한 것은 무엇인가? 왜 바꾸려 하는가?

## 6. KPI와 의사결정 게이트

| KPI | 최초 측정 시점 | 통과 기준 후보(아직 실측 없음) |
|---|---|---|
| 고객문제 확인 | Phase 0/1 | 12–15건 인터뷰 중 8건 이상 반복되는 구체적 pain point 확인 |
| 가상 모델 재현성 | Phase 1 | 고정 seed·동일 환경 재현성 100% |
| 안전·누수 테스트 | Phase 1 | 중요 안전 테스트 100% 통과 |
| 연구 작업 가치 | Phase 1/2 | 기존 작업 대비 시간·오류·재현성 중 1개 이상 개선 |
| 연구용 데이터 계약 | Phase 2 | 1개 이상의 적법한 코호트 접근 |
| 임상적 모델 성능 | Phase 2/3 | 사전 합의한 기준선, 보정, 순편익 게이트 통과 |
| 구매 검증 | Phase 3 | 실제 예산 소유자의 유료 파일럿 또는 조달 조건 구체화 |

KPI 수치들은 기획상의 탐색 목표이고 현재 성취도·외부 인증이 아니다.

## 7. 위험·비용·전략적 선택

- **자료 접근 실패:** 합성 연구용 도구로 범위를 제한, 임상 성능 주장 없이 연구 서비스 판매 가설만 확인.
- **예측성능 불충분:** 억지로 모델 복잡도를 올리지 말고 Pathway/Guard 중심의 연구 분석 제품으로 피봇.
- **검사 정책 효과 식별 불가:** 의사결정 모델은 전적으로 가상 시나리오로 한정.
- **임상의 협업 부재:** 병원용 제품 계획 중단, 통계 연구 시뮬레이터 유지.
- **인증 부담/책임 리스크:** 초기 연구용 워크벤치에서 매출 가능성을 평가하고 임상 CDS 전환은 별도 투자 판단.
- **브랜드 중복:** `dPCR`이 digital PCR로도 널리 사용되므로 서비스 검색·상표·도메인 충돌 조사 필요.
- **창업자 종속성:** 의료진, 통계전문가, 보안/법률 자문 확보 전 고위험 기능을 출시하지 않음.

## 8. 우선 작성할 영업 자료

- 1페이지 buyer-specific problem brief (임상연구팀용).
- 5분 합성 환자 시나리오 동영상(의학적 예측 주장 없는 데모).
- 1페이지 보안/데이터 경계.
- 1페이지 검증 상태표 및 model card.
- 연구기관의 평가 기준과 수용시험에 맞춘 유료 파일럿 SOW 초안.

## 9. 협력·출판 전략

- 첫 연구는 '범암종 예측에서 시간을 반영한 모델의 보정과 검증'처럼 **검증 가능한 작은 질문**으로 시작.
- 별도 소아 뇌종양 연구는 연구참여·데이터 계약·윤리·저자 기준을 분리하고 결과를 함부로 전이하지 않음.
- 출판·영업 양쪽에서 동일한 근거수준 구분: 합성 PoC / 후향적 연구 / 외부 검증 / 실제현장 영향 평가.
- 논문·제품 설명에 연구자 개인 또는 지도 관계의 승인·소속을 임의로 기재하지 않음.
